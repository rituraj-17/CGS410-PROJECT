## Research Question

> **"Do LLMs produce Human-like Dependency Tree Structures?"**

This project compares the syntactic structure of sentences generated by Large Language Models against naturally occurring human-written sentences drawn from annotated treebanks — examining whether LLMs internalize human-like syntactic organization across multiple languages.

---

## Background & Motivation

Dependency parsing represents sentence structure as a tree where each word is linked to a syntactic "head" via a typed grammatical relation. Properties of these trees — such as how deep they grow, how many dependents each word takes, and how far apart words are from their syntactic heads — are known to vary systematically across languages and text genres.

If LLMs truly model human language, their output should yield dependency trees with statistical properties (depth, arc distance, branching) that closely match treebank data from the same language. Divergences would suggest that LLMs, despite producing fluent text, may encode a subtly different syntactic grammar from the one humans use.

---

## Methodology

The pipeline follows these steps:

1. **Human data extraction** — CoNLL-U formatted treebanks (SUD format) are parsed to extract sentence-level syntactic metrics.
2. **LLM data collection** — Sentences generated by an LLM are passed through a neural dependency parser (Stanza) to produce dependency trees.
3. **Metric computation** — For each sentence (human or LLM), three structural metrics are computed.
4. **Comparison & visualization** — Metrics are compared across the two groups using summary statistics, length-controlled analysis, and plots.

Both datasets are processed using identical metric extraction logic, ensuring a fair apples-to-apples comparison.

## Data Sources

### Human Data — SUD Treebanks

Human sentences come from **Surface-Universal Dependencies (SUD)** treebanks in CoNLL-U format. The example run in the code covers four languages:

| Language | Code |
|----------|------|
| English | `en` |
| Hindi | `hi` |
| German | `de` |
| Spanish | `es` |

The treebanks provide gold-standard syntactic annotations produced by human annotators, serving as the ground-truth baseline for "human-like" dependency structure.

### LLM Data

LLM-generated sentences are loaded from plain text (`.txt`) or JSONL files — one sentence per line, or a JSON object with a `"text"` field per line. These are parsed by the Stanza neural dependency parser to generate dependency trees for metric extraction.

The large raw output (`output_part_1.csv`, ~49,000 rows, 1.3 MB) holds sentence-level metrics for both sources across all languages.

## Tools & Models Used

### Neural Dependency Parser — Stanza (Stanford NLP)

**Stanza** is used to parse LLM-generated text into dependency trees. It provides a full NLP pipeline including:
- Tokenization
- Part-of-speech tagging
- Lemmatization
- Dependency parsing

Stanza's dependency models are pretrained on Universal Dependency treebanks per language, using neural architectures (BiLSTM-based parsers). The pipeline is initialized per language with `tokenize`, `pos`, `lemma`, and `depparse` processors.

### CoNLL-U Parser — `conllu`

The `conllu` Python library is used to read and iterate over `.conllu` formatted treebank files for the human (SUD) data, extracting token-level head and dependency relation information.

### Visualization — Matplotlib + Seaborn

Three types of plots are produced to compare the two distributions visually:
- **Dependency distance boxplot** — compares arc length distributions
- **Tree depth boxplot by language** — compares structural depth across languages
- **Sentence length vs. dependency distance scatter with regression** — examines whether sentence length explains distance differences

## Syntactic Metrics Computed

For every sentence in both the human and LLM corpora, three structural properties are measured:

### 1. Tree Depth
The maximum root-to-leaf path length in the dependency tree. Deeper trees indicate more hierarchically nested syntactic structure. Computed as the longest chain from any root node to its deepest leaf.

### 2. Mean Node Arity
The average number of direct dependents (children) per node. This measures how "branchy" the tree is — higher arity means more words are attached directly to a common head (flat structure), while lower arity implies more sequential/hierarchical chaining.

### 3. Dependency Distance (per arc)
For each dependency arc connecting a word to its head, the absolute token distance `|head_index - dependent_index|` is recorded. This is a well-studied psycholinguistic measure: humans are known to prefer shorter dependency distances (Dependency Length Minimization), so comparing human vs. LLM distributions here is particularly informative.

All metrics can be computed with or without punctuation tokens (`--exclude-punct` flag), and a **length-matched analysis** (sentences of 10–20 tokens) is automatically produced to control for the confound that LLMs may generate longer sentences.

## Key Observations

Based on the code design, metric choices, and the structure of the outputs, the following analytical comparisons are the focus of the project:

**Dependency Distance**
Humans are known (from psycholinguistic research) to favor short dependency arcs — a principle called Dependency Length Minimization. The boxplot (`dep_distance_boxplot.png`) directly tests whether LLMs show a similar preference or produce systematically longer arcs. If LLM distances are higher, their sentences may be syntactically "heavier" even when fluent.

**Tree Depth**
Greater tree depth signals more deeply embedded clausal or phrasal structure. The language-stratified boxplot (`tree_depth_boxplot.png`) checks if LLMs produce shallower or deeper trees than humans, and whether this varies by language — for instance, German and Hindi (verb-final/morphologically rich languages) may show starker divergences than English.

**Sentence Length as a Confounder**
LLMs tend to generate longer sentences than those in treebanks. The `length_vs_distance_scatter.png` and the length-matched analysis (10–20 tokens) control for this: if gaps in dependency distance vanish under length matching, the observed difference is an artifact of sentence length rather than a genuine structural divergence.

**Cross-language Generalization**
By covering English, Hindi, German, and Spanish — languages with very different syntactic typologies (word order, morphology, head-directionality) — the study tests whether any Human vs. LLM structural gap is language-universal or language-specific.

**Mean Node Arity**
If LLMs use shallower trees with more siblings per node (higher arity), their structure may resemble a "flatter" parse — potentially reflecting training on web text or formatting conventions that differ from treebank-style prose.

## How to Run

The script is fully CLI-driven. Provide SUD treebank paths (glob patterns) and/or LLM sentence files per language.

**Basic example (English only):**

```bash
python dependency_analyzer.py \
  --sud en "path/to/sud/en/*.conllu" \
  --llm en "path/to/llm/en.txt"
```

**Full multi-language run (as used in the project):**

```bash
python dependency_analyzer.py \
  --sud en "sud/en/*.conllu" \
  --sud hi "sud/hi/*.conllu" \
  --sud de "sud/de/*.conllu" \
  --sud es "sud/es/*.conllu" \
  --llm en "llm/en.txt" \
  --llm hi "llm/hi.txt" \
  --llm de "llm/de.txt" \
  --llm es "llm/es.txt"
```

**Optional flags:**

| Flag | Effect |
|------|--------|
| `--exclude-punct` | Remove punctuation tokens before computing metrics |
| `--use-gpu` | Use GPU for Stanza parsing (if available) |
| `--batch-size N` | Number of sentences per Stanza batch (default: 64) |
| `--out-csv PATH` | Custom output path for sentence-level CSV |
| `--out-summary-csv PATH` | Custom path for summary CSV |
| `--out-plot PATH` | Custom path for the dependency distance boxplot |

All outputs are written to an `outputs/` directory by default.
